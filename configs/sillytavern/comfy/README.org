* SillyTavern ⇄ ComfyUI workflows (tiers A, C, F)

Verified on the =comfyui= VM (RTX 4090 passthrough) with **ComfyUI 0.43.0** on
2026-10-30. All three workflows were executed end-to-end on the real GPU and the
output PNGs have the expected dimensions.

Files are **API-format** workflow JSON (the format SillyTavern's ComfyUI
integration expects — ComfyUI's "Save (Format) → API"). Identical copies are also
saved in ComfyUI's own workflow library under the same filenames, so they can be
opened and tweaked on the canvas.

**Model files live in** =$=/media/models/comfyui/= (extra-model-paths config), so
the =.safetensors= names below are exactly what SillyTavern/ComfyUI dropdowns show.

**Where SillyTavern puts them** — Settings → *Image Generation* → pick the
ComfyUI backend, then paste/upload the JSON into the ComfyUI **workflow** box
(stored as =extension_settings.sd.comfy_workflow=) and set the ComfyUI URL
(=extension_settings.sd.comfy_url=). Because the request is issued by the
*browser*, the URL has to match how you reach SillyTavern: if ST is served over
=https://sillytavern.ts.peteches.co.uk=, use **https://comfyui.ts.peteches.co.uk**
(Caddy → =comfyui.spaniel-cordylus.ts.net:8188=, WebSocket upgrade included);
=http://192.168.51.206:8188= gets blocked as mixed content.

**Placeholder rules** (SillyTavern replaces a placeholder only when it is a
*standalone quoted string value* in the JSON):

- ="%prompt%"=, ="%negative_prompt%"=, ="%seed%"= → SillyTavern's prompt, negative
  and seed. They are already placed on the prompt / negative / sampler nodes.
- ="%width%"= / ="%height%"= are available if you want ST to drive the canvas size;
  they are currently pinned numbers instead, because each model has hard size
  preferences.
- Do **not** embed these tokens inside a longer string, and do not put them in
  the pinned trigger-phrase nodes (nodes labelled "Pinned LoRA trigger tokens").
- =steps= / =cfg= / =sampler_name= / =scheduler= are deliberately **pinned** in
  the JSON rather than taken from ST: ST's sampler/scheduler lists do not map
  cleanly onto ComfyUI's enums, and these turbo models only work with the
  pinned combination.

* SillyTavern-side settings (verified against ST 1.19.0 on =agents=)

ST's ComfyUI workflow library is **its own folder**, not ComfyUI's:
=$=/var/lib/sillytavern/sillytavern/data/default-user/user/workflows/= (the
=ComfyUI Workflow= dropdown is a server-side =readdir= of that dir —
=/srv/sillytavern/src/endpoints/stable-diffusion.js=, =getComfyWorkflows=).
The three files were installed there directly (owned =sillytavern:sillytavern=,
mode 664), so no upload is needed — just pick one in the dropdown. The copies in
**ComfyUI's** library are Web-UI format (canvas-editable); the copies in ST's
folder are API format, which is what ST sends verbatim to =/prompt=.

Concrete levers, in priority order:

1. **Workflow selector** (Settings → Image Generation → =ComfyUI Workflow=) —
   =sillytavern_sdxl_lightning4.json= is the sane chat default. It is stored in
   the shared =default-user= profile, so tier choice is per-profile, not
   per-chat; use separate ST profiles (or the =!-command/QuickReply route) if
   you want per-chat tiers. The =Connect= button next to the URL must be green:
   ST populates its Model / Sampler / Scheduler / VAE dropdowns from
   =/api/sd/comfy/{models,samplers,schedulers,vaes}=.
2. **Prompt prefix and tag processing** — ST prepends =prompt_prefix= (plus any
   per-character prefix) to the text it injects into ="%prompt%"=, and style
   presets overwrite =prompt_prefix= when applied. Booru-ish quality tags help
   SDXL and hurt natural-language photoreal models, so clear the prefix for C/F
   and tick =minimal_prompt_processing= there.
3. **Per-character prompts** — =character_prompts= / =character_negative_prompts=
   (both currently ={}=) hold per-character text that ST appends to the prompt;
   fill them with costume/pose/anatomy details instead of editing the workflow.
4. **Custom placeholders** — the workflow editor's "Add placeholder" rows write
   =comfy_placeholders= entries =[{find, replace}]=; ST replaces ="%<find>%"=
   as a whole quoted value and runs =replace= through its macro/!=!-expression
   engine, so per-character LoRA names, strengths or trigger tokens can live in
   character cards. Built-in =%model% %vae% %sampler% %scheduler% %steps%
   %scale% %width% %height%= also work and are fed from ST's Image-Gen parameter
   fields (ST reads the legal values straight from ComfyUI, so they do map) —
   but for tiers C/F keep the pinned values, because CFG 1 / 8 steps is the only
   window where those models look right, and ST's current fields would send
   steps 6 / CFG 2.5.
5. **Batch size** — the graphs ship =batch_size: 1= in =EmptyLatentImage=;
   raising it to 2-4 in tier A costs almost nothing (warm sampling is 1.1 s) and
   multiplies the chance of a keeper, so it is the cheapest quality lever. Do it
   in ST's workflow editor (pencil icon) or edit the file in the folder above.
6. **Cost discipline** — a model swap costs 9-25 s, so alternate tiers only
   between scenes, and be aware that =function_tool= lets the LLM start a
   generation on its own.

* Alternating tiers costs a model swap

Keeping two tiers resident does not fit in 24 GB, so switching A → C → F pays
the cold-load number each time (≈9–25 s). For a chat session it is worth
picking *one* tier per scene: A for inline instant shots, C for the "make it
pretty" pass, F when you need on-image text or a specific layout.

* Operational notes / follow-ups

- The 4090 is single-purpose: koboldcpp and ComfyUI cannot both hold it. The LLM
  now runs on the Intel Arc B70 via Strata, so koboldcpp should stay stopped
  (=herd stop koboldcpp=) during image work; consider =auto-start? #f= for
  koboldcpp and =auto-start? #t= for ComfyUI in =peteches/systems/comfyui.scm=.
- The ComfyUI update bumped =torch= from 2.14.0+cu130 to **2.15.0+cu132**; the
  =nvidia-cudnn-cu13= / =nvidia-cublas-cu13= runtime pins in
  =peteches/services/comfyui.scm= may need the matching bump, and
  =--use-sage-attention= should be avoided for Z-Image-style models (it renders
  them black/garbled — use =--use-pytorch-cross-attention= or the per-graph
  KJNodes sage patch).
- Housekeeping: =/media/models/comfyui/loras/peteches/bas/*-state/= training
  output dirs pollute the LoRA list, and =Comfy.Execution.PreviewMethod= is best
  set to =latent2rgb= to avoid VAE-decoding every preview.
- Nothing in this directory is referenced by the Guix build; the files are
  assets to upload into SillyTavern (kept in the repo for versioning).
