* SillyTavern ⇄ ComfyUI workflows (tiers A, C, F, F', F'')

Tiers A / C / F were executed end-to-end on the real GPU (RTX 4090 passthrough,
**ComfyUI 0.43.0**) on 2026-10-30 and the output PNGs have the expected
dimensions.

Tiers F' / F'' (the character-reference ones) were **schema-validated against
the live ComfyUI 0.43.0 =/object_info=** — every =class_type=, required input,
link, output index and combo enum — with SillyTavern's substitution simulated in
source order, and they pass clean. They have **not** been GPU-run since the
fixes below; see "Test plan" at the end of this file.

Files are **API-format** workflow JSON (the format SillyTavern's ComfyUI
integration expects — ComfyUI's "Save (Format) → API"). Identical copies are also
saved in ComfyUI's own workflow library under the same filenames, so they can be
opened and tweaked on the canvas.

**Model files live in** =$=/media/models/comfyui/= (extra-model-paths config), so
the =.safetensors= names below are exactly what SillyTavern/ComfyUI dropdowns show.

**Where SillyTavern puts them** — Settings → *Image Generation* → pick the
ComfyUI backend, then paste/upload the JSON into the ComfyUI **workflow** box
(stored as =extension_settings.sd.comfy_workflow=) and set the ComfyUI URL
(=extension_settings.sd.comfy_url=). Because the request is issued by the
*browser*, the URL has to match how you reach SillyTavern: if ST is served over
=https://sillytavern.ts.peteches.co.uk=, use **https://comfyui.ts.peteches.co.uk**
(Caddy → =comfyui.spaniel-cordylus.ts.net:8188=, WebSocket upgrade included);
=http://192.168.51.206:8188= gets blocked as mixed content.

**Placeholder rules** (SillyTavern replaces a placeholder only when it is a
*standalone quoted string value* in the JSON):

- ="%prompt%"=, ="%negative_prompt%"=, ="%seed%"= → SillyTavern's prompt, negative
  and seed. They are already placed on the prompt / negative / sampler nodes.
- ="%width%"= / ="%height%"= are available if you want ST to drive the canvas size;
  they are currently pinned numbers instead, because each model has hard size
  preferences.
- Do **not** embed these tokens inside a longer string, and do not put them in
  the pinned trigger-phrase nodes (nodes labelled "Pinned LoRA trigger tokens").
- =steps= / =cfg= / =sampler_name= / =scheduler= are deliberately **pinned** in
  the JSON rather than taken from ST: ST's sampler/scheduler lists do not map
  cleanly onto ComfyUI's enums, and these turbo models only work with the
  pinned combination.

** How the prompt references the image

=TextEncodeMOSSImageEdit= takes an **edit instruction**, not a tag soup, and its
own description says: "Encodes an edit instruction with reference images … The
references are used at the size they come in, **scale them first**."

But ST only substitutes ="%prompt%"= when it is a *standalone quoted value*, so
the instruction and the scene prompt cannot share one string. The graph
therefore joins them with the native =StringConcatenate= node
(=comfy_extras.nodes_string=, inputs =string_a= / =delimiter= / =string_b=):

| Node | Slot | Content |
|------+------+---------|
| =22 StringConcatenate= | =string_a= | the **fixed edit instruction** — "the provided reference image is the single source of truth for this character's identity; keep face, hair colour, eye colour, skin tone, build unchanged; only pose/framing/expression/clothing/lighting/setting may differ" |
| | =delimiter= | newline |
| | =string_b= | ="%prompt%"= — ST's scene text, substituted correctly because it is the whole value |
| =17 TextEncodeMOSSImageEdit= | =prompt= | ← =22= (a link, not a literal) |

Put any LoRA trigger token at the **start of =string_a=** — that is where ST's
=prompt_prefix= and per-character prompt also land, and it is the only place a
trigger can live without breaking the =%prompt%= substitution.

** Mandatory =ImageScale=

Node 20 (lanczos → 1024², center crop) is part of the graph, not an
optimization. ST avatars are small squares — and 1×1 when a character has no
avatar — and =TextEncodeMOSSImageEdit='s VAE-encode of the reference dies with
"Kernel size can't be greater than actual input size". Keep the scale target
equal to =EmptyLatentImage='s size.

** Autogrow =images= input — API-format spelling

=images= is a ComfyUI-v3 *Autogrow* input (verified from =/object_info=:
prefix =image_=, **min 1, max 10**). In API format — which is what ST sends —
each slot must be a **flat dotted key**:

#+begin_src json
"images.image_0": ["20", 0]
#+end_src

Neither ="images": [link]= nor ="images": {"image_0": [link]}= validates
(=required_input_missing / images.image_0=).

** Why not just use =%char_avatar%= four times

ST has exactly **two** built-in image tokens, =%char_avatar%= and =%user_avatar%=,
and =%char_avatar%= is **non-deterministic in group chats**. From
=getCharacterAvatarUrl()= (=index.js:3269=):

#+begin_src js
if (context.groupId) {
    const lastMessageAvatar = /* last non-user, non-system message */ ?.original_avatar;
    const randomMemberAvatar = groupMembers[Math.floor(Math.random() * groupMembers.length)];
    return formatCharacterAvatar(lastMessageAvatar || randomMemberAvatar);
}
#+end_src

So in a group it is whoever spoke last, else a **random member**. That is fine
for a single-character insert; it is useless for "render Amy on the left and
Beth on the right". Deterministic casting has to come from custom placeholders.

** Custom placeholders can carry base64 — and can alias the built-ins

=comfy_placeholders= entries are =[{find, replace}]=; ST applies
=replaceAll('"%<find>%"', JSON.stringify(substituteParams(replace)))=. Two
properties make this sufficient:

1. =substituteParams= is ST's full macro engine, and ={{getvar::name}}= /
   ={{getglobalvar::name}}= are registered macros (=public/scripts/variables.js:249,259=).
   So a chat variable holding raw base64 can be injected as an image reference.
2. **Custom placeholders run BEFORE the avatar substitutions.** The order in
   =generateComfyImageCommon= is: built-in scalars (=model/vae/sampler/…=) →
   =comfy_placeholders= → =%user_avatar%= → =%char_avatar%=. A custom
   placeholder whose =replace= is literally =%user_avatar%= therefore still gets
   resolved by the later avatar pass — you can **alias** a slot to either
   built-in, and per-slot ordering becomes fully controllable.

Recipe for deterministic group casting:

| find | replace | Effect |
|------+---------+--------|
| =ref2= | =%user_avatar%= | slot 2 = your persona's avatar |
| =ref2= | ={{getvar::beth_b64}}= | slot 2 = whatever b64 an STscript put in =beth_b64= |
| =ref3= | ={{getglobalvar::cast_beth}}= | global (cross-chat) variant |

Set these in Settings → Image Generation → the ComfyUI workflow editor's
"Add placeholder" rows.

** Unused slots must be DELETED, not left unset

There is no way to remove a JSON key by textual substitution, so an unset slot
still feeds *something* to the encoder. With the **updated** loader an unset
slot decodes to the inert 1×1 and node 22's instruction tells the model to
ignore blank/solid-colour squares; with the **old** loader it hard-fails
(=%ref3%= base64-decodes to 3 garbage bytes, =Image.open= raises, the input-dir
fallback misses, =ValueError=). Either way it is wasted conditioning.

To run with fewer references, delete the loader + its =ImageScale= + the
matching ="images.image_N"= key in node 17 (ST's workflow editor is a plain JSON
textarea, so this is a 10-second edit). Slots need not be contiguous — Autogrow
keys are named, so =image_0= + =image_2= is legal.

** Adding more slots

Autogrow allows **10**. Duplicate a loader+=ImageScale= pair and add
="images.image_4": ["<scale_id>", 0]= etc. Each extra reference is one more
1024² VAE encode, so if it gets slow drop the latent *and every* =ImageScale=
target to 512 together.

* The custom node — =custom_nodes/moss_avatar_loader.py=

Registers =LoadImageFromBase64OrUrl= ("Load Image From Base64/URL/char_avatar",
category =peteches/SillyTavern=), outputs =IMAGE= + =MASK= like comfy's
=LoadImage= so it feeds =ImageScale → TextEncodeMOSSImageEdit= unchanged.

Accepts bare base64 (the ST case), a =data:image/...;base64,= URI, an =http(s)=
URL, or a filename in ComfyUI's input directory (Web-UI testing).

Revised to treat "no reference" as a *normal state* rather than an error. All of
these mean "nothing here": empty/whitespace; an unsubstituted built-in
(=%char_avatar%=, =char_avatar=); an unsubstituted custom placeholder (=%ref3%=,
=%anything%=); an unexpanded macro (={{getvar::foo}}=); the literal strings
=undefined= / =null=; and ST's =PNG_PIXEL= **by value** (1×1 pure white). The
value check matters — a deliberate 1×1 avatar is legitimate, so size alone must
never trigger it.

Two real defects fixed:

- A **duplicated** =elif text.startswith("data:image/")= branch made the second
  one dead code, and the first *raised* on a 1×1 white pixel while the =else=
  branch (bare base64 — the actual ST path) did **not** check at all. So ST's
  own =PNG_PIXEL= fallback silently became a white reference instead of being
  detected. Detection is now in one place, on every path.
- Token matching was a substring test (="char_avatar" in text=), which also
  misfires on legitimate filenames such as =my_avatar.png=. It is now an exact
  =^%[^%\s]+%$= match plus an explicit allow-list of the two bare spellings.

New **optional** =on_missing= widget (default =transparent_1px=, alternative
=error=). Optional on purpose: workflows that omit it stay valid against the
previously deployed revision, so the workflow-side =%char_avatar%= fix did not
have to wait on a node redeploy. Set it to =error= while debugging to make a
missing token fail loudly instead of rendering a white square.

Deployed at =/srv/comfyui/custom_nodes/peteches_sillytavern_nodes/= on the
=comfyui= VM. It is a shepherd-managed =guix shell --container= process: copy
the file in and =pkill -f "python3 main.py --listen"= triggers auto-restart.

**Gotcha:** substitution happens in the *browser* on ST's generation path only.
Opening these workflows in ComfyUI's Web UI leaves the tokens literal — the node
then yields an inert 1×1 reference. For manual tests put a real =https://= URL
or a =data:= URI in the widget.

* Verified ST 1.19.0 substitution rules

Everything below was read out of
=/srv/sillytavern/public/scripts/extensions/stable-diffusion/index.js=
(=generateComfyImageCommon=, lines 4221–4290) rather than inferred.

** The one rule that causes most failures

A token is replaced **only when it is a complete, standalone quoted JSON string
value**. =replaceAll('"%prompt%"', …)= — the pattern includes both percent signs
*and* both quote characters. Embedding a token in a longer string
(="moss_xvstyle %prompt%"=) or prefixing it
(="data:image/png;base64,%char_avatar%"=) silently does nothing.

** Substitution order

| Step | Tokens | Value |
|------+--------+-------|
| 1 | =%prompt%=, =%negative_prompt%=, =%seed%=, =%denoise%=, =%clip_skip%= | from Image-Gen settings (seed =-1= → random) |
| 2 | =%model%=, =%vae%=, =%sampler%=, =%scheduler%=, =%steps%=, =%scale%=, =%width%=, =%height%= | =extension_settings.sd[ph]= |
| 3 | =%<find>%= for each =comfy_placeholders= entry | =JSON.stringify(substituteParams(replace))= — **full macro engine** |
| 4 | =%user_avatar%= | persona avatar base64, else =PNG_PIXEL= |
| 5 | =%char_avatar%= | character avatar base64, else =PNG_PIXEL= |

Steps 4–5 are gated: ST only fetches an avatar if =/%char_avatar%/gi= matches the
workflow text. Steps 3–5 matter in that order — a custom placeholder can alias
=%char_avatar%= or =%user_avatar%= and still be resolved by the later pass.

** Avatar encoding

Base64 **without** any =data:image/png;base64,= prefix (ST takes
=dataUrl.split(',')[1]=). That is exactly why ArtVenture's =LoadImageFromUrl=
cannot be used: it requires the prefix and splits on =,=. No client can
concatenate the prefix on, so the custom node is not optional.

Fallback when an avatar cannot be fetched is =PNG_PIXEL= — a 1×1 white PNG,
hard-coded at =index.js:71= and mirrored as =PNG_PIXEL_B64= in the node. If you
change ST, check that constant still matches.

** ST never uploads images

=/srv/sillytavern/src/endpoints/stable-diffusion.js= =comfy.post('/generate')=
POSTs =request.body.prompt= straight to =<url>/prompt= and polls =/history/<id>=.
There is no =/upload/image= call anywhere in the server or the extension, so the
=LoadImage= (filename) pattern from ordinary ComfyUI workflows is unavailable —
references must travel **as data** inside the workflow JSON.

** Avatars are behind auth

Character avatars are served by =router.use('/characters/*', …)= in
=src/users.js:1214=, mounted under =/api/users= with =req.user= resolution. A
server-side fetch of some *other* character's avatar from ComfyUI would need
credentials, which is why the custom-placeholder + ={{getvar::}}= route is
preferable to pointing the node at an ST URL.

Concrete levers, in priority order:

1. **Workflow selector** (Settings → Image Generation → =ComfyUI Workflow=) —
   =sillytavern_sdxl_lightning4.json= is the sane chat default. It is stored in
   the shared =default-user= profile, so tier choice is per-profile, not
   per-chat; use separate ST profiles (or the =!-command/QuickReply route) if
   you want per-chat tiers. The =Connect= button next to the URL must be green:
   ST populates its Model / Sampler / Scheduler / VAE dropdowns from
   =/api/sd/comfy/{models,samplers,schedulers,vaes}=.
2. **Prompt prefix and tag processing** — ST prepends =prompt_prefix= (plus any
   per-character prefix) to the text it injects into ="%prompt%"=, and style
   presets overwrite =prompt_prefix= when applied. Booru-ish quality tags help
   SDXL and hurt natural-language photoreal models, so clear the prefix for C/F
   and tick =minimal_prompt_processing= there.
3. **Per-character prompts** — =character_prompts= / =character_negative_prompts=
   (both currently ={}=) hold per-character text that ST appends to the prompt;
   fill them with costume/pose/anatomy details instead of editing the workflow.
4. **Custom placeholders** — the workflow editor's "Add placeholder" rows write
   =comfy_placeholders= entries =[{find, replace}]=; ST replaces ="%<find>%"=
   as a whole quoted value and runs =replace= through its macro/!=!-expression
   engine, so per-character LoRA names, strengths or trigger tokens can live in
   character cards. Built-in =%model% %vae% %sampler% %scheduler% %steps%
   %scale% %width% %height%= also work and are fed from ST's Image-Gen parameter
   fields (ST reads the legal values straight from ComfyUI, so they do map) —
   but for tiers C/F keep the pinned values, because CFG 1 / 8 steps is the only
   window where those models look right, and ST's current fields would send
   steps 6 / CFG 2.5.
5. **Batch size** — the graphs ship =batch_size: 1= in =EmptyLatentImage=;
   raising it to 2-4 in tier A costs almost nothing (warm sampling is 1.1 s) and
   multiplies the chance of a keeper, so it is the cheapest quality lever. Do it
   in ST's workflow editor (pencil icon) or edit the file in the folder above.
6. **Cost discipline** — a model swap costs 9-25 s, so alternate tiers only
   between scenes, and be aware that =function_tool= lets the LLM start a
   generation on its own.

* Alternating tiers costs a model swap

Keeping two tiers resident does not fit in 24 GB, so switching A → C → F pays
the cold-load number each time (≈9–25 s). For a chat session it is worth
picking *one* tier per scene: A for inline instant shots, C for the "make it
pretty" pass, F when you need on-image text or a specific layout.

* Test plan for tiers F' / F''

Schema validation is done and passes; what remains is GPU/runtime verification,
in this order. Steps 1–3 need no node redeploy.

1. **Confirm the avatar actually arrives.** In ST pick
   =sillytavern_moss_sft_4step_ref.json=, open the browser devtools console and
   generate once. =generateComfyImageCommon= logs the final serialized prompt
   (=console.log= at =index.js:4283=). Search it for the node-14 value: it must
   be a long base64 string, **not** =char_avatar= and **not** the 68-char
   =PNG_PIXEL=. If it is =PNG_PIXEL=, the character card has no avatar — set one
   (Character → Avatar).
2. **Confirm identity hold.** Give a character a distinctive card avatar (red
   hair, blue eyes) and generate the same scene three times with =seed= =-1=.
   Before the fix every run drifted; after it the three should share hair/eye
   colour and face shape. This is the actual acceptance criterion.
3. **Confirm the prompt references the image.** Temporarily set node 22's
   =string_a= to something contradicting the reference (e.g. "the character has
   green hair"). If the output obeys =string_a= over the reference, the
   instruction is reaching the encoder; revert afterwards.
4. **Deploy the updated node**, then re-run 1. Required for tier F'' with unset
   slots, and for the =PNG_PIXEL=-detection and =on_missing= fixes:
   #+begin_src sh
   scp configs/sillytavern/comfy/custom_nodes/moss_avatar_loader.py \
       comfyui:/srv/comfyui/custom_nodes/peteches_sillytavern_nodes/
   ssh comfyui 'pkill -f "python3 main.py --listen"'   # shepherd auto-restarts
   #+end_src
   Verify the new widget landed: =/object_info/LoadImageFromBase64OrUrl= should
   now list an =optional.on_missing= enum.
5. **Confirm multi-slot Autogrow.** The schema says =images= takes =image_0=…
   =image_9=, but only =image_0= has ever been executed on this host. Enqueue
   tier F'' with all four slots set to *distinct* real images (any =https://=
   URLs will do for a bench test) and confirm (a) validation passes and (b) four
   distinguishable identities appear. If =image_1+= is rejected, fall back to
   one =ImageBatch= chain into =image_0= and re-test.
6. **Group casting.** Add the =ref2= / =ref3= / =ref4= custom placeholders
   (start with =ref2= → =%user_avatar%=, the zero-setup case that exercises the
   ordering discovery). Then move to ={{getvar::…}}= with an STscript that
   populates the variable from the intended character's avatar.

* Known gaps

- **=%char_avatar%= is random in group chats.** Not fixable from the workflow —
  it is ST's =getCharacterAvatarUrl()= behaviour. Tier F'' sidesteps it by
  driving slots from custom placeholders; slot 0 keeps the built-in only as a
  convenience default.
- **No IPAdapter / InsightFace / PuLID / InstantID path.** Verified absent from
  the live =/object_info= (1845 nodes): the only IPAdapter node is
  =ImpactIPAdapterApplySEGS= (Impact Pack, SD-era), and there are no
  face-embedding nodes at all. MOSS-Image's edit-LoRA reference latents are the
  available mechanism here. For SDXL (tier A) the classic face-ID route is also
  unavailable, so a **trained per-character LoRA** in node 4 remains the
  strongest consistency option; the reference workflow is what you use when no
  LoRA has been trained.
- **=edit_format= is a guess.** The node offers =ai-toolkit=, =ai-toolkit
  (kv_cache off)= and =Moss-Image-Edit=, and the right value is whichever layout
  =moss_image_edit_lora_bf16.safetensors= was trained with. The files ship
  =Moss-Image-Edit=; if identity transfer is weak, try =ai-toolkit= before
  concluding the LoRA is at fault. =(kv_cache off)= recomputes references every
  step — slower, but the references also attend to the image being generated.
- **CFG 1.0 makes the negative inert**, so node 9 is decoration in both files.
  It matters only for the 50-step quality recipe (=steps 50= / =cfg 3= /
  =sgm_uniform=, drop the speed LoRA), where =TextEncodeMOSSImageEdit='s own
  description advises using the edit node for the negative too.
- **Nothing here is wired into the Guix build.** =configs/sillytavern/comfy/= is
  assets-only: the JSONs must be copied into ST's workflow directory and the
  node into ComfyUI's =custom_nodes=. Neither =peteches/services/sillytavern.scm=
  nor =peteches/services/comfyui.scm= references this directory, so a redeploy
  does not ship these changes.
