Tiers A / C / F were executed end-to-end on the real GPU (RTX 4090 passthrough,
**ComfyUI 0.43.0**) on 2026-10-30 and the output PNGs have the expected

Tier F' — character reference, **1–4 references from a single file**, so solo

**Placeholder rules** (SillyTavern replaces a placeholder only when it is a
*standalone quoted string value* in the JSON):

- ="%prompt%"=, ="%negative_prompt%"=, ="%seed%"= → SillyTavern's prompt, negative
  and seed. They are already placed on the prompt / negative / sampler nodes.
- ="%width%"= / ="%height%"= are available if you want ST to drive the canvas size;
  they are currently pinned numbers instead, because each model has hard size
  preferences.
- Do **not** embed these tokens inside a longer string, and do not put them in

* Diagnosing a bad generation — read ComfyUI's =/history=, not the workflow file

The workflow JSON in this repo is **not** what ran. Two independent copies can
drift: the file in ST's workflow directory may have been hand-edited in ST's
workflow editor, and the repo copy is only updated by hand. Before blaming a
graph, pull what actually executed:

#+begin_src sh
curl -s http://comfyui.spaniel-cordylus.ts.net:8188/history?max_items=25
#+end_src

Each entry's =prompt[2]= is the exact node graph ComfyUI ran, **after** ST's
substitution — so it shows the truth about placeholders. That is how the tier-F'
regression was diagnosed: the bad run showed ={"image": "char_avatar"}= still
literal (ST never substituted it), ={"text": "moss_xvstyle %prompt%"}= still
literal, no speed LoRA, =cfg 5= and a 512² latent. All three bugs, visible in
one dump.

This also caught a **repo drift** the other way: the good-looking no-ref runs
were using =cfg 3= + =sgm_uniform=, while every file in this repo said =cfg 1.0=
+ =simple=. The deployed base workflow had been tuned in ST's editor and never
written back. All three MOSS files here are now reconciled to the values that

* Tier F' — =sillytavern_moss_sft_4step_ref.json= (character reference, 1–4 refs)

**One workflow for solo and group scenes.** There is no separate group file any
more — reference count is decided at runtime by how many slots ST fills, so you
never have to switch workflows between chats.

| Stage | Nodes |
|-------+-------|
| Model chain | =1 UNETLoader → 4 LoraLoaderModelOnly(4-step speed) → 5 LoraLoader(edit, model+clip) → 11 KSampler= |
| References | =14= (=%char_avatar%=), =30= (=%ref2%=), =32= (=%ref3%=), =34= (=%ref4%=) — each a =LoadImageFromBase64OrUrl= |
| Collapse | =40 SillyTavernReferenceSheet= → one 1024² sheet |
| Positive | =22 StringConcatenate=(instruction, ="%prompt%"=) → =17 TextEncodeMOSSImageEdit= (clip from **node 5 output 1**) |
| Negative | =24 StringConcatenate=(identity protection, ="%negative_prompt%"=) → =23 TextEncodeMOSSImageEdit= with the **same sheet** |
| Sample | =10= 1024² latent, =11 KSampler= 4 steps / cfg 3.0 / euler / sgm_uniform |

** Why one file can serve any reference count

The blocker was that ST builds the workflow by textual substitution, so there is
no way to *delete* an unused =images.image_N= key — an unset slot still feeds
something to the encoder. =SillyTavernReferenceSheet= solves it by dropping
blanks **inside the node**:

- each unset token (=%ref2%= left literal, an unset ={{getvar::}}=, ST's
  =PNG_PIXEL= fallback) makes its loader emit a 1×1 placeholder
- the sheet node detects those and drops them
- it tiles only the real references: **1 → full frame**, 2 → side by side,
  3–4 → 2×2

With a single reference present the output is that reference at full 1024²,
**pixel-identical** to what a dedicated single-reference graph produces
(asserted in the node's test — =maxdiff=0.0000=). So the solo case pays nothing
for the flexibility.

Tradeoff: with 2+ references each character gets fewer pixels. If multi-
character fidelity proves too weak, see "Native Autogrow alternative" below.

** How the prompt references the image

=TextEncodeMOSSImageEdit= takes an **edit instruction**, not a tag soup, and its
own description says "The references are used at the size they come in, **scale
them first**." But ST only substitutes ="%prompt%"= as a *standalone quoted
value*, so instruction and scene cannot share one string. The native
=StringConcatenate= node (=comfy_extras.nodes_string=) joins them:

| Slot | Content |
|------+---------|
| =string_a= | short edit instruction — keep face/hair/eye/skin/build exactly as shown; panels read left-to-right then top-to-bottom; ignore blank panels |
| =delimiter= | one space |
| =string_b= | ="%prompt%"= — substituted correctly because it is the whole value |

**Keep =string_a= short.** An earlier revision carried a multi-sentence
paragraph of meta-instructions ("never blend or average features…", "ignore any
reference that is a blank or solid-colour square…"); MOSS edit wants a concise
instruction and the verbose version is a plausible quality regressor. LoRA
trigger tokens go at the **start** of =string_a= — that is where ST's
=prompt_prefix= and per-character prompt also land.

** Deterministic casting in group chats

=%char_avatar%= is **non-deterministic in groups**. From =getCharacterAvatarUrl()=
(=index.js:3269=): it returns the last non-user speaker's avatar, else a
**random** group member. Fine for a solo insert, useless for "Amy left, Beth
right".

Custom placeholders fix this. =comfy_placeholders= entries are =[{find,
replace}]=, applied as =replaceAll('"%<find>%"',
JSON.stringify(substituteParams(replace)))=. Two properties matter:

1. =substituteParams= is the full macro engine, and ={{getvar::name}}= /
   ={{getglobalvar::name}}= are registered macros (=public/scripts/variables.js:249,259=),
   so a chat variable holding raw base64 can be injected as a reference.
2. **Custom placeholders run BEFORE the avatar passes** (order in
   =generateComfyImageCommon=: built-in scalars → =comfy_placeholders= →
   =%user_avatar%= → =%char_avatar%=). A placeholder whose =replace= is literally
   =%user_avatar%= therefore still resolves — you can **alias** a slot to either
   built-in and control slot ordering exactly.

| find | replace | Effect |
|------+---------+--------|
| =ref2= | =%user_avatar%= | slot 2 = your persona (zero setup) |
| =ref2= | ={{getvar::beth_b64}}= | slot 2 = whatever an STscript stored |
| =ref3= | ={{getglobalvar::cast_beth}}= | global (cross-chat) variant |

Set these in Settings → Image Generation → the workflow editor's "Add
placeholder" rows. Unset ones are harmless — the sheet node drops them.

** Native Autogrow alternative (max fidelity, fixed count)

=images= is a v3 *Autogrow* input — **min 1, max 10** slots, prefix =image_=
(confirmed from =/object_info=). To give every character a full-resolution
reference instead of a sheet panel, delete node 40 and wire each loader
straight into its own slot:

#+begin_src json
"images.image_0": ["14", 0],
"images.image_1": ["30", 0]
#+end_src

API format requires the **flat dotted key** — neither ="images": [link]= nor
="images": {"image_0": [link]}= validates (=required_input_missing /
images.image_0=). The cost: the reference count is then baked into the file, so
you are back to one workflow per cast size. Slots need not be contiguous
(=image_0= + =image_2= is legal).

Each reference must be pre-scaled — either an =ImageScale= per slot, or keep
node 40 for the ones you want sheeted. Never feed a raw ST avatar in: the
VAE-encode dies with "Kernel size can't be greater than actual input size".

** The proven recipe — =moss-ref-edit-{4step,20step}.json= in ComfyUI's library

ComfyUI's own workflow library (=/var/lib/comfyui/comfyui/user/default/workflows/=)
already contained two hand-tuned MOSS reference graphs, dated **after** this
repo's copies. They are the authority on what works on this host, and they
contradicted three choices this file previously made:

| Item | This repo (wrong) | Proven graph |
|------+-------------------+--------------|
| =edit_format= | =Moss-Image-Edit= (a guess) | **=ai-toolkit=** |
| edit LoRA node | =LoraLoaderModelOnly= (model only) | **=LoraLoader=** — model **and clip** |
| CLIP into the encoders | straight from =CLIPLoader= | **from the edit LoRA's CLIP output** |
| negative | plain =CLIPTextEncode= | **=TextEncodeMOSSImageEdit= with the same reference** |

The =LoraLoader= point is the important one: the edit LoRA has a text-encoder
side, and if the CLIP is not passed through it, the edit instruction is encoded
by an un-adapted encoder — so the reference binds weakly no matter what the
prompt says. Both the positive *and* negative encoders must take CLIP from the
edit LoRA (output index 1).

The reference-conditioned negative matters because =cfg= is 3.0, not 1.0, so the
negative is live. The proven text is identity-protective:

#+begin_example
different face, different person, changed identity, deformed face, blurry face,
extra people, changed hair colour, short hair
#+end_example

Node 24 here prepends exactly that to ST's =%negative_prompt%=.

Model chain, as proven: =1 UNETLoader → 4 LoraLoaderModelOnly(speed) →
5 LoraLoader(edit, model+clip) → 11 KSampler=. The =20step= variant simply omits
node 4 and sets =steps 20= — confirming the speed LoRA is what makes 4 steps
viable.

* The custom nodes — =custom_nodes/=

** =moss_avatar_loader.py= — =LoadImageFromBase64OrUrl=

Outputs =IMAGE= + =MASK= like comfy's =LoadImage=. Accepts bare base64 (the ST
case), a =data:image/...;base64,= URI, an =http(s)= URL, or a filename in
ComfyUI's input directory (Web-UI testing).

Treats "no reference" as a *normal state* rather than an error. All of these
mean "nothing here": empty/whitespace; an unsubstituted built-in
(=%char_avatar%=, =char_avatar=); an unsubstituted custom placeholder (=%ref3%=);
an unexpanded macro (={{getvar::foo}}=); the literals =undefined= / =null=; and
ST's =PNG_PIXEL=, detected **by size** (any 1×1 image).

=PNG_PIXEL= is a 1×1 fully **transparent black** pixel (mode =LA=, value =(0, 0)=)
— *not* white, despite what this file and the node both used to assert. Testing
== (255, 255, 255)= never matched it, so a missing avatar sailed through as a
black reference. Size is the reliable signal: one pixel cannot describe a
character, and the default =on_missing= drops it rather than raising.

Three defects fixed:

- A **duplicated** =elif text.startswith("data:image/")= made the second branch
  dead code, and the first *raised* on a placeholder while the =else= branch
  (bare base64 — the path ST actually uses) did **not** check at all. So ST's
  own =PNG_PIXEL= fallback silently became a black reference instead of being
  detected. Detection is now unified across all paths.
- Token matching was a substring test (="char_avatar" in text=), which also
  misfires on legitimate filenames like =my_avatar.png=. Now an exact
  =^%[^%\s]+%$= match plus an allow-list of the two bare spellings (19/19 test
  cases).
- Added an **optional** =on_missing= widget (=transparent_1px= | =error=).
  Optional on purpose so graphs that omit it stay valid against older revisions
  of the node. Set =error= while debugging to make a missing token fail loudly
  instead of rendering a blank panel.

** =reference_sheet.py= — =SillyTavernReferenceSheet=

Drops blank slots and tiles the rest into one square sheet (see tier F' above).
Inputs: =target_size= (required) + =image_1..image_4= (all optional); outputs
=sheet= (IMAGE) and =reference_count= (INT, for debugging/conditioning).

Blank detection is **size- and value-based**: any 1×1 image (regardless of
colour — =PNG_PIXEL= is transparent *black*, so a colour test silently fails), or
any larger solid-colour frame (std dev ≈ 0), which also catches blanks already
upscaled by an intervening =ImageScale=. Cells are filled with a
resize-to-cover + center-crop so panels keep their aspect ratio.

Tested (45 assertions in =custom_nodes/test_nodes.py=, runnable without ComfyUI
or a GPU via =guix shell=): node registration, blank detection, cover-crop
geometry, layout selection for n=1..4, output always exactly square (including
odd sizes like 832), count correctness, the all-blank case returning a
**full-size** neutral sheet (a 1×1 would crash the VAE-encode downstream), and
the single-reference fidelity guarantee. Run them with:

cd configs/sillytavern/comfy

** =__init__.py= — mappings must be MERGED

ComfyUI reads =NODE_CLASS_MAPPINGS= off the package =__init__=. Two
=from .x import *= lines would silently **overwrite** each other and unregister
the first module's nodes — the classic "only the last module in the pack loads"
bug. The =__init__= therefore imports the modules and =update()=s the dicts
explicitly. Add new modules the same way; do not star-import them.

* Verified ST 1.19.0 substitution rules

Read out of
=/srv/sillytavern/public/scripts/extensions/stable-diffusion/index.js=
(=generateComfyImageCommon=, lines 4221–4290) rather than inferred.

** The one rule that causes most failures

A token is replaced **only when it is a complete, standalone quoted JSON string
value**. =replaceAll('"%prompt%"', …)= — the pattern includes both percent signs
*and* both quote characters. Embedding a token in a longer string
(="moss_xvstyle %prompt%"=) or prefixing it
(="data:image/png;base64,%char_avatar%"=) silently does nothing. This single
rule caused two of the three tier-F' bugs.

** Substitution order

| Step | Tokens | Value |
|------+--------+-------|
| 1 | =%prompt%=, =%negative_prompt%=, =%seed%=, =%denoise%=, =%clip_skip%= | from Image-Gen settings (seed =-1= → random) |
| 2 | =%model%=, =%vae%=, =%sampler%=, =%scheduler%=, =%steps%=, =%scale%=, =%width%=, =%height%= | =extension_settings.sd[ph]= |
| 3 | =%<find>%= for each =comfy_placeholders= entry | =JSON.stringify(substituteParams(replace))= — **full macro engine** |
| 4 | =%user_avatar%= | persona avatar base64, else =PNG_PIXEL= |
| 5 | =%char_avatar%= | character avatar base64, else =PNG_PIXEL= |

Steps 4–5 are gated: ST only fetches an avatar if =/%char_avatar%/gi= matches
the workflow text — which is why a percent-less =char_avatar= widget meant no
avatar was ever even looked up.

** Avatar encoding

Base64 **without** any =data:image/png;base64,= prefix (ST takes
=dataUrl.split(',')[1]=). That is exactly why ArtVenture's =LoadImageFromUrl=
cannot be used: it requires the prefix and splits on =,=. No client can
concatenate the prefix on, so the custom node is not optional.

Fallback when an avatar cannot be fetched is =PNG_PIXEL= — a 1×1 fully
**transparent black** PNG (mode =LA=, value =(0, 0)=; *not* white, as this file
once claimed), hard-coded at =index.js:71= and mirrored as =PNG_PIXEL_B64= in the
node. If you upgrade ST, check that constant still matches.

** ST never uploads images

=src/endpoints/stable-diffusion.js= =comfy.post('/generate')= POSTs
=request.body.prompt= straight to =<url>/prompt= and polls =/history/<id>=. There
is no =/upload/image= call anywhere in the server or the extension, so the
=LoadImage= (filename) pattern from ordinary ComfyUI workflows is unavailable —
references must travel **as data** inside the workflow JSON.

** Avatars are behind auth

Character avatars are served by =router.use('/characters/*', …)= in
=src/users.js:1214=, mounted under =/api/users= with =req.user= resolution. A
server-side fetch of some *other* character's avatar from ComfyUI would need
credentials, which is why the custom-placeholder + ={{getvar::}}= route is
preferable to pointing the node at an ST URL.

Concrete levers, in priority order:

1. **Workflow selector** (Settings → Image Generation → =ComfyUI Workflow=) —
   =sillytavern_sdxl_lightning4.json= is the sane chat default. It is stored in
   the shared =default-user= profile, so tier choice is per-profile, not
   per-chat; use separate ST profiles (or the =!-command/QuickReply route) if
   you want per-chat tiers. The =Connect= button next to the URL must be green:
   ST populates its Model / Sampler / Scheduler / VAE dropdowns from
   =/api/sd/comfy/{models,samplers,schedulers,vaes}=.
2. **Prompt prefix and tag processing** — ST prepends =prompt_prefix= (plus any
   per-character prefix) to the text it injects into ="%prompt%"=, and style
   presets overwrite =prompt_prefix= when applied. Booru-ish quality tags help
   SDXL and hurt natural-language photoreal models, so clear the prefix for C/F
   and tick =minimal_prompt_processing= there.
3. **Per-character prompts** — =character_prompts= / =character_negative_prompts=
   (both currently ={}=) hold per-character text that ST appends to the prompt;
   fill them with costume/pose/anatomy details instead of editing the workflow.
4. **Custom placeholders** — the workflow editor's "Add placeholder" rows write
   =comfy_placeholders= entries =[{find, replace}]=; ST replaces ="%<find>%"=
   as a whole quoted value and runs =replace= through its macro/!=!-expression
   engine, so per-character LoRA names, strengths or trigger tokens can live in
   character cards. Built-in =%model% %vae% %sampler% %scheduler% %steps%
   %scale% %width% %height%= also work and are fed from ST's Image-Gen parameter
   fields (ST reads the legal values straight from ComfyUI, so they do map) —
   but for tiers C/F keep the pinned values, because CFG 1 / 8 steps is the only
   window where those models look right, and ST's current fields would send
   steps 6 / CFG 2.5.
5. **Batch size** — the graphs ship =batch_size: 1= in =EmptyLatentImage=;
   raising it to 2-4 in tier A costs almost nothing (warm sampling is 1.1 s) and
   multiplies the chance of a keeper, so it is the cheapest quality lever. Do it
   in ST's workflow editor (pencil icon) or edit the file in the folder above.
6. **Cost discipline** — a model swap costs 9-25 s, so alternate tiers only
   between scenes, and be aware that =function_tool= lets the LLM start a
   generation on its own.

* Alternating tiers costs a model swap

Keeping two tiers resident does not fit in 24 GB, so switching A → C → F pays
the cold-load number each time (≈9–25 s). For a chat session it is worth
picking *one* tier per scene: A for inline instant shots, C for the "make it
pretty" pass, F when you need on-image text or a specific layout.

* SillyTavern prompt templates and the reference system

**Short answer: the workflow needs no template change, but the templates are
actively wrong for MOSS and should be changed anyway.**

The identity instruction lives in the workflow (node 22's =string_a=), not in
ST, so nothing *has* to change for references to work. But ST's image-generation
prompt templates (Settings → Image Generation → "Prompt templates",
=extension_settings.sd.prompts=, defaults at =index.js:174=) were written for
SD1.5/SDXL booru models and fight a natural-language edit model on two counts:

1. **They demand tag soup, not prose.** The =CHARACTER=, =FACE=, =USER= and =NOW=
   templates all say "a detailed **comma-delimited list of keywords and
   phrases**", "**Do not write in full sentences**", and force a prefix like
   ='full body portrait,'=. MOSS-Image edit wants an instruction — the proven
   graph's positive is a plain sentence ("A photo of the same young woman
   sitting in a seaside cafe booth by the window…").
2. **Without =minimal_prompt_processing=, ST mangles prose.** =processReply()=
   (=index.js:2901=) strips all quotes, converts newlines to =", "=, and
   **strips non-alphanumeric characters**. Tick =minimal_prompt_processing= and
   it only collapses whitespace and NFD-normalises. For tiers C/F this is not
   optional.

Also clear **=prompt_prefix=** (default =best quality, absurdres, aesthetic,=) for
tiers C/F — booru quality tags help SDXL and hurt natural-language models.

** One template genuinely helps for references

The =NOW= template instructs the LLM: "Only mention characters by using pronouns
('he','his','she','her') or neutral nouns". That is *already* the right instinct
for a reference workflow — identity comes from the image, not the text — but it
then also demands "keywords to describe {{char}}'s physical appearance", which
duplicates and can contradict the reference.

For tier F', a template that tells the LLM the reference exists is better. Add
to whichever template you use (they accept ={{char}}= / ={{user}}= macros):

#+begin_example
A reference image of the character is supplied separately, so do NOT describe
their face, hair colour, eye colour, skin tone or build — those come from the
reference. Write ONE natural-language sentence (not a keyword list) describing
only the setting, pose, framing, expression, clothing, lighting and mood. Refer
to the character as "the same person".
#+end_example

For **group** scenes, extend it to name who is in shot and in what order, since
the sheet's panels are positional (left→right, top→bottom) and that ordering is
the only thing tying a panel to a character:

#+begin_example
If more than one character is present, state who is in the first and second
reference panel respectively, matching the order the characters are listed.
#+end_example

** Interactive / function-tool mode

With =function_tool= enabled the LLM can start a generation itself, using the
=TOOL= template as the tool description ("an exhaustive description of the
desired image that will allow an artist or a photographer to perfectly recreate
it"). That wording invites exactly the appearance re-description a reference
makes redundant, so update it with the same guidance if you use that mode. Note
it also means the LLM can fire a 9–25 s generation unprompted.

** Per-character text still has a place

=character_prompts= / =character_negative_prompts= (per-character appendices to
the prompt) are the right home for costume, pose habits and anatomy details that
are *not* visible in the avatar — not for hair and eye colour, which the
reference now carries. Keeping those out of the text is what stops a card's
stale description from fighting the image.

* Known gaps

- **Execution is proven; quality is not.** The graph runs end-to-end on the 4090
  and the sheet logic behaves exactly as designed, but no output has been judged
  against a real character avatar yet. Test steps 4–5 are the gate.
- **ST-side deployment is outstanding.** The JSON is not in ST's workflow
  directory, so ST is still generating with whatever is there now. See "Deploy
  status" for the two ways to finish it.
- **ST avatars are small.** Upscaling a ~200px card avatar to a 1024² reference
  panel is lossy. A dedicated high-res reference image (the proven graphs use
  =leah_canonical_ref.png= from ComfyUI's input dir) will beat the card avatar;
  the loader also accepts an =https://= URL or an input-dir filename, so you can
  point a slot at one directly instead of relying on =%char_avatar%=.
- **=%char_avatar%= is random in group chats.** Not fixable from the workflow —
  it is ST's =getCharacterAvatarUrl()= behaviour. Slot 1 keeps the built-in only
  as a convenience default; use custom placeholders for anything deterministic.
- **2+ references share a 1024² frame**, so per-character detail is halved (2
  refs) or quartered (3–4). The Autogrow alternative restores full resolution at
  the cost of fixing the reference count per file.
- **No IPAdapter / InsightFace / PuLID / InstantID path.** Verified absent from
  the live =/object_info= (1845 nodes): the only IPAdapter node is
  =ImpactIPAdapterApplySEGS= (Impact Pack, SD-era), and there are no
  face-embedding nodes at all. MOSS-Image's edit-LoRA reference latents are the
  available mechanism here, and the same is true for SDXL (tier A) — so a
  **trained per-character LoRA** in node 4 remains the strongest consistency
  option. The reference workflow is what you use when no LoRA has been trained.
- **Repo ⇄ deployed drift is easy and silent.** The good images were produced by
  =cfg 3= + =sgm_uniform= while every file here said =cfg 1.0= + =simple=; ST's
  workflow editor writes to its own directory and nothing syncs back. Worse,
  **=/history= is in-memory and is wiped by every ComfyUI restart** — so the
  evidence cannot be re-read after a restart. Capture it into this directory
  after any tuning session.
- **ComfyUI's library holds the real source of truth for tuned graphs.** The
  =moss-ref-edit-*.json= files there were newer and more correct than anything in
  this repo, and are not version-controlled anywhere. Consider copying them into
  =configs/sillytavern/comfy/= so the next person does not have to rediscover
  =ai-toolkit= and the =LoraLoader=-vs-=LoraLoaderModelOnly= distinction from a
  live box.
- **Nothing here is wired into the Guix build.** =configs/sillytavern/comfy/= is
  assets-only: JSONs must be copied into ST's workflow directory and the nodes
  into ComfyUI's =custom_nodes=. Neither =peteches/services/sillytavern.scm= nor
  =peteches/services/comfyui.scm= references this directory, so =guix deploy=
  ships none of it. The node deploy in particular is a manual =scp= + restart.
