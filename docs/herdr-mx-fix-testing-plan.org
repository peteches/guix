* Constraints that shape the plan

1. **The fixes are client-side; the client does not run on this VM.**
   =herdr-mx= reaches the desktops through =base-packages= (peteches/home/modules/base.scm:172) and this VM
   only runs the *server* (shepherd =herdr-server=, peteches/home/modules/claude-workstation.scm:157).
   Layers 1–3 below can run here; the behavioural proof needs dagon or nyarlothotep.

2. **Version parity is a hard gate, and failing it is the documented incident.**
   =version_line_matches_current= compares the *full* version string (=0.8.2-mx.<build-id>=). If a fork-built
   client does not print exactly what =command -v herdr= prints on the remote, the probe fails and add-remote
   **self-provisions its own exe into the remote's =~/.local/bin/herdr=** — the crash-loop/cascade from
   2026-09-26. ⇒ *Build one artifact and install it on both sides in the same window.*
   (=build.rs= derives FULL_VERSION from =HERDR_BUILD_CHANNEL= + =HERDR_BUILD_ID=; a dirty tree also appends a
   =-dirty.<hash>= build commit, so commit before building.)

3. **Toolchain gap.** =rust-toolchain.toml= pins Rust **1.96.1**; Guix only has **rust 1.93.0** (no =rust-1.96=),
   and this VM has no =cargo=, =rustc=, =just=, no =nix=, and =gh= is **not authenticated**. Guix *does* have
   =zig 0.15.2= (the version the vendored libghostty-vt requires), =cmake=, =ninja=, =musl=, =cargo-nextest=.
   A previous build succeeded here (=target/debug= dated 2026-09-26, warm 164 MB =~/.cargo/registry=,
   =vendor/libghostty-vt/zig-out= present), so a =guix shell= build is plausible — but unproven at 1.93.

* The short version — no Guix changes, no deploy, no static binary

Three facts found after writing the layers below collapse most of the ceremony:

1. **Guix's rust 1.93.0 already compiles this tree.** =target/debug/deps/herdr-bb9535b2fd2cf40b= (built here
   2026-09-26, i.e. at =79803d18=) embeds =1.93.0 (254b59607 2026-01-19)=. The 1.96.1 pin is a rustup
   convention, not a hard requirement — Guix's cargo ignores =rust-toolchain.toml=.
2. **A static (musl) build is impossible with Guix's rust, and unnecessary.** Its =lib/rustlib= ships only
   =x86_64-unknown-linux-gnu= and Guix has no =rustup= package. Static musl needs the rustup installer or CI.
   A dynamic Guix build runs fine on the machine that built it — which is all a test needs.
3. **Version parity can be satisfied with a build env var instead of a deploy.** =build.rs::full_version()=
   composes FULL_VERSION purely from =HERDR_BUILD_CHANNEL= + =HERDR_BUILD_ID= (no commit, no =-dirty= marker).
   Building with the *deployed* build id makes =remote_binary_matches= (version line + protocol) pass against
   the existing workstation server → **no self-provisioning into =~/.local/bin/herdr=** → the 2026-09-26
   incident cannot recur. Safe because these commits leave =PROTOCOL_VERSION= 21 / =WIRE_ABI_EPOCH= 3 alone.

** 3a. #91 — agent focus targets the public pane id, not the terminal id
   - Disposable named session, ≥2 panes with distinguishable agents.

     focus lands on the intended pane.
   - **Run the same steps against the installed =79803d18= build first** and record the wrong behaviour.
     Without that baseline the fix is unfalsifiable.

** 3b. Event-loop stall → freezes + stuck "offline" badge
   The new observable is the heartbeat: =client event loop heartbeat= at info level, every 60 s
   (=LOOP_HEARTBEAT_INTERVAL=), in =~/.config/herdr/herdr-client.log= — a wedged loop reads as a *gap*.
   1. Idle: heartbeat present at ~60 s cadence, no gaps.
   2. Load: burst =SupervisorSummaryChanged(main)= / =ImmediateFocused= refreshes — several panes with
      chatty output plus agent-state churn across ≥2 attached remotes (this is where the inline
      =refresh_main_summary_from_api()= used to back up the bounded =event_tx= and stall every other
      producer: secondary reconnects, remote summary-subscription threads).
   3. Assert: no heartbeat gap > ~2 intervals, no =main supervisor refresh failed= cluster, no =app.shutdown=,
      sidebar badge does not stick on "offline" while the connection is healthy, no SIGSEGV.
   4. **Baseline the same load on the pinned build** — the freeze/badge symptom should reproduce there and
      not on the candidate. That contrast *is* the test result.
   5. Coalescing check: a burst should produce one refresh, not N (=pending_main_refresh=).

* Risks and gotchas

- **Rust 1.93 vs 1.96.1** — the local route may simply not compile. Layer 0's =cargo check= probe answers
  this in minutes; if it fails, CI (route A) is the only build path.
- **glibc ≠ musl** — a locally built binary is for Layers 1–3 only. Never package or deploy it: the shipped
  artifact is static-pie musl with no patchelf, and a glibc build would also break the "identical pin on both
  machines" property in a way that is invisible until add-remote self-provisions.
- **Dirty tree changes the build id** (=build_commit= appends =-dirty.<hash>=) — commit or stash before any
  build whose version string matters.
- **Testing inside a live herdr session** — always clear =HERDR_SOCKET_PATH= / =HERDR_CLIENT_SOCKET_PATH=,
  or the candidate will attach to (or worse, restart) the production server.
- **Three accounts on this VM** — the workstation runs a herdr server for peteches, criticalgrind and ygo;
  a server-side deploy touches all three, and the desktops' remote lists point at them.
- **Fork CI publish permissions** — =preview-mx.yml='s publish job needs =contents: write=; on a fork with
  Actions newly enabled, the first run may need the workflow permission granted in repo settings.
- **Don't declare success from a green test run.** The four new unit tests already pass on the author's
  machine by construction; the evidence that matters is Layer 3's before/after contrast under load and the
  Layer 5 soak.
